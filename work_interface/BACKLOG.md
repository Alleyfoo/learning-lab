## B-1 — `verify_prep` must become genuinely observational

**Status: open. Raised after W1-I.**

### The smell

`verify_prep.py` is a *verifier*, but several of its checks run the pack's own
reporters, which write `RESULTS.*`, `FIDELITY.*`, `AUTHORITY.*` and
`TOKENIZATION.*` into the pack. On a **completed** pack that means the
verification command mutates the very evidence it is verifying.

This has now happened repeatedly:

```text
W1-B / W1-C  results regenerated by a prep run; restored from HEAD
W1-F         flagged in the closure
W1-I         AUTHORITY/RESULTS regenerated twice while fixing reporter pins;
             restored from 6ce7bd1 both times
```

The bytes have been restored every time and no evidence has been lost. That is
not the point. **A verifier that mutates what it verifies is exactly the class
of authority defect this lab exists to eliminate** — the same shape as the A4
backstop writing into the run directory it audits, or a grader repairing an
artifact it grades.

### What it should be

```text
read-only by construction   the verifier must not be able to write into runs/
                            or into any reporter output
dry-run reporters           checks that need a reporter's verdict call its
                            pure function, or run it against a temp copy
refuse on a used pack       a prep verifier asked to verify a pack that has
                            already produced evidence should REFUSE, not run
                            and overwrite
```

The third item alone would have prevented every occurrence above.

### Scope guard

Fixing this must not alter any frozen pack's recorded `PREP_CHECK.txt`, and must
not change what the checks assert — only where they are allowed to write. Frozen
packs keep their existing `verify_prep.py`; the corrected verifier applies to
new packs.

## B-2 — reporter constants should be derived, not pinned

**Status: partially done (W1-I). Open for older packs.**

Cloning a pack repeatedly carried constants the new pack could not satisfy:

```text
W1-F  authority_report used A4.verdict instead of worker_verdict  -> false CONTESTED 3/3
W1-I  CONSUMPTION_MARKERS held the W1-A fixture titles            -> false NO 6/6
W1-I  grade.py skill_match pinned to the r2 hash                  -> false no on the whole r3 arm
```

Each was caught and corrected additively, and each cost a closure section. W1-I
now derives consumption markers from its own declared fixtures and accepts any
declared revision, with `verify_prep` check 20 asserting both. The general rule
— **a reporter constant that names an input must be derived from that input, or
asserted against it** — should be applied when the next pack is cut, not
retrofitted to frozen ones.
