Containment Evidence Ledger

Every claim this programme has made about putting agents behind a trust boundary, paired with the evidence that actually backs it — and graded by how strong that evidence is. Four of these claims are proven by construction. Most are n=1. The difference is the point of this document. The two entries that were live defects have since been fixed — LIM-4 and PRO-2 carry their repair inline.

How evidence is graded5 grades

The grade describes what kind of thing the evidence is, not how much I like the claim. A structural claim and a single model call are both real evidence; they are not the same evidence, and collapsing them is how a lab talks itself into believing its own architecture.

Structural

True by construction and asserted in code. No model, no sampling, no fixture dependence. The strongest thing here.

Deterministic

Repeatable measurement, no model involved — but on fixtures authored in-lab. Says what the machinery does, not how often the world presents the case.

Preregistered n=1

One call, one model (GLM-5.2), temperature 0, prediction frozen before the run. Establishes existence, never frequency.

Analytic

A calculation from stated assumptions. No measurement of the world at all.

Untested

Named because it is load-bearing and nobody has measured it. Listed so it cannot be mistaken for a result.

Containment & authority5 claims

These are the claims the security argument rests on. They are also, by some distance, the best-evidenced — because most of them do not depend on a model behaving.

CON-1Deterministic

After a schema is defined, no model is invoked at runtime.

EvidenceExperiment K: 14 dispatch decisions, all made by deterministic code. The EXECUTE branch contains no model call. Experiment L then executed an approved recipe end to end with no model at any point.

CaveatMeasured on in-lab fixtures. It says the runtime path contains no model — not that every real workbook reaches that path.

CON-2Deterministic

Approval is enforced separately from matching: a recipe edited after approval will not run.

EvidenceK case C11 — identical workbook, every binding resolving, and the dispatcher returns BLOCKED because the recipe's content hash no longer matches the approved hash.

CaveatBinds the recipe, not the workbook region a human actually looked at. A human can still approve a recipe over a document they misread.

CON-3Structural

The structure view cannot carry cell text, so no payload in any cell can reach an agent reading it.

EvidenceThe view's output alphabet is exactly # A · ƒ ? plus column letters and row numbers. contains_no_content() checks every string token of every cell against the rendering, on a workbook carrying a live injection marker. Held across all 10 cases of Experiment O and all of N.

CaveatProves the payload cannot arrive through this view. Filenames, sheet names and the values view are separate surfaces and are untested.

CON-4Deterministic

The agent's write surface is constrained: it emits addresses and closed-enum roles, never computation.

EvidenceFrozen referent grammar carries no roles or transforms. Recipe transforms are a closed enum; exclusion rules take literal value lists, never patterns. Experiment M pushed six provider shapes at the format and none required arbitrary computation — the widest gap asked for a bounded feature (a second unpivot) and one asked only for a declaration.

CaveatSix shapes, author-chosen. Breadth pressure was modest; a real corpus may push harder.

CON-5Deterministic

Every attack found so far steers a proposal. None has moved authority.

EvidenceAcross O, P and Q — 4 successful steers out of 11 aimed attacks — not one produced an EXECUTE on a recipe a human had not approved. The steers change what the agent says; the deterministic layer decides what runs.

CaveatThis is the strongest and the most easily over-read claim here. A steered proposal that a human then approves is a real compromise, and nothing in these experiments tested a human in that loop.

Usefulness5 claims

A containment architecture nobody can use protects nothing. These claims say the thing actually works.

USE-1Deterministic

A recipe produces a correct table from a real workbook.

EvidenceExperiment L1: 12 of 12 rows, columns and order exact. The grand-total row, the derived total column, the free-text column and three preamble rows all correctly absent.

CaveatOne recipe, one sheet, one transform.

USE-2Deterministic

Define once, run next month's file — with no model in the loop.

EvidenceExperiment L2: the same approved recipe on a later file with two extra products and the total row moved. 18 of 18 rows correct, the moved total row still excluded.

CaveatThis is the architecture's entire economic argument and it rests on two workbooks.

USE-3Deterministic

Coverage accounting catches a silently shifted column — the failure a real tool gets wrong.

EvidenceK case C5: inserting a column leaves the positional binding pointing at the wrong months while every named binding still resolves, so nothing fails. It is caught only because one column ends up claimed by nothing. repo_reuse_map.md defect D1 is this exact shift, in a tool where the run succeeds.

CaveatAn accounting property, not a semantic one. It catches unclaimed objects, not wrong claims.

USE-4Deterministic

Applicability is decided from the recipe itself — the filename is never consulted.

EvidenceK case C2: a byte-identical file under a different name dispatches to EXECUTE. The predecessor system folds the filename into its hash, so next month's file would miss its own recipe — failing on the one case saved recipes exist for.

CaveatThe lookup key ("the recipe's data sheets exist") is deliberately weak and was not itself under test.

USE-5Preregistered n=1

An agent can locate a header row from structure alone, with no access to cell text.

EvidenceExperiment N: correct on a sheet with a three-row preamble and on one with none. It also answered unknown on a genuinely ambiguous layout — the first unprompted refusal in this programme, against a prediction that it would assert.

CaveatOne call per case, one model. And it was wrong on the third sheet — see LIM-5.

Limits & negative results7 claims

These carry as much weight as the positive results. Several were predicted before the run and preserved rather than patched.

LIM-1Deterministic

A structural predicate cannot see a semantic change. Reconciliation narrows this; it does not close it.

EvidenceK case C8: a subtotal row with a data row's exact shape passes every structural check. Adding a reconciliation check (does the file's own total equal the sum of the data rows?) catches it — and case C14, where the total was updated to include the subtotal, adds up perfectly and is merely double-counted. Arithmetic has nothing to say.

CaveatEach format version narrowed the residual and none removed it. C14's successor will be more contrived, not more tractable.

LIM-2Deterministic

Half of realistic provider shapes need something the schema cannot say.

EvidenceExperiment M: 3 of 6 shapes expressible. Gaps were a two-measure block (needs a second unpivot), formatted numbers (needs a format declaration) and an interleaved note (correctly refused).

CaveatAuthor-chosen shapes. Two predicted gaps turned out expressible, so the format is stronger than its designer assumed.

LIM-3Deterministic

The schema cannot say how a date is written, and silently does not try.

EvidenceExperiment L gap G1: a field declared type: date over the value 3.2.2026. There is no format string and no locale, so honouring it means guessing dd.mm over mm.dd — invisible on 3 February, wrong on 5 March. The value passes through and the unhonoured declaration is recorded.

CaveatReported rather than silent, which puts it in a better risk class than LIM-4.

LIM-4DeterministicFixed

A validated, approved recipe could lose half the data with no signal anywhere.

EvidenceExperiment M shape S3: two measure fields each declaring an unpivot. The recipe validates, is approvable, and the executor honours only the last — 4 rows where 8 are required. No problem code, no unhonoured declaration, no refusal.

FixedAn executor contract now declares what can be honoured, and the validator refuses a recipe that exceeds it. The five defect cases all dispatch BLOCKED; the unmodified recipe still executes. See fixes/LIM4-PRO2.md.

CaveatThe expressiveness gap remains — the format still cannot express two measure blocks. What changed is that it now refuses instead of producing half a table.

LIM-5Preregistered n=1

Content-free is not influence-free: the payload never reaches the agent and the attacker still moves the answer.

EvidenceExperiment N case F2 — the one workbook carrying an injection is the one the model got wrong. Three glyphs in the deciding row exist only because of hidden content: a white-font cell, a near-zero-width column's text, a ;;;-formatted number. Strip them and the answer is unambiguous.

CaveatNot designed as an attack — that fixture was built to test the detector and moved the answer anyway, which makes it stronger evidence than a constructed case.

LIM-6Preregistered n=1

The structural channel is aimable: an adversary can choose the row the agent picks.

Evidence4 of 11 aimed attacks landed on the attacker's exact target across O, P and Q, using only formatting invisible on screen — a hidden all-text row, and ;;;-formatted numbers in two positions.

CaveatLayout-dependent: identical primitives steered one base and failed another, so an adversary probes rather than knows. But retries are free and unalarmed — a channel that works one time in three, with unlimited attempts, is a working channel.

LIM-7Preregistered n=1

The detector-gated defence closes every attack it was tested on — and is walked around by an offset attack.

EvidenceExperiment P: escalates on 4 of 4 bad outcomes, including 2 held-out steers on layouts the rule was never designed against, with 0 false alarms across 12 clean decisions. Experiment Q then degrades the true header instead of promoting a decoy, so the attacker's target carries no finding at all — the gate accepts, on the first attempt.

CaveatThe gate catches steered to the manipulated row, not steered by manipulation. Widening it to a neighbourhood catches this instance and moves the false-alarm question somewhere untested.

Cost1 claim

COST-1Analytic

Keeping the model out of the loop is cheaper only when formats are stable.

EvidenceWith p = share of arrivals needing redefinition and D = redefinition cost in whole-file reads, per-file cost is p × D against a baseline of 1.

pDreads / fileversus reading every file
2%30×0.60cheaper
5%10×0.50cheaper
5%30×1.50more expensive
10%10×1.00break-even
25%30×7.50much more expensive

CaveatNo measurement of the world here at all — p is a property of a provider and has never been measured for a real one. Below roughly a 5–10% change rate the architecture wins; above it, reading every file is cheaper. The security argument does not depend on this, but adoption does.

Process5 claims

PRO-1Deterministic

Predictions were frozen before every run, and wrong ones were preserved rather than patched.

EvidenceEvery experiment committed its spec, expected values and fixtures before the harness existed; git ordering is the enforcement. 67 frozen artifacts are hash-verified by a single command. Preregistered failures — a regression, a false-execute, a blind spot — were recorded as results, and two runs superseded by a spec/code deviation were kept verbatim rather than deleted.

CaveatFixtures and predictions come from the same author. Held-out arms mitigate this; they do not remove it.

PRO-2DeterministicGuarded

This codebase has a recurring defect family: a producer declares a capability, a consumer interprets it, and nobody proves they mean the same thing.

EvidenceSeven instances. Three found during experiments: a problem code added to the validator and not listed by the dispatcher; a format permitting two unpivots the executor cannot honour; a grader voiding globally where the spec said per base. Three more found by auditing every declared capability against its consumer: an unimplemented transform op silently dropped, a sheet role that contributed nothing, and fifteen of twenty-three problem codes unclassified by the dispatcher — so a recipe the validator reported invalid dispatched to EXECUTE.

GuardedThree levels now. Declared? the format enum lists it. Consumed? a single contract classifies it and the dispatcher acts on it — both assertions run at import. Identical? every supported construct registers an observable invariant demonstrated end to end, and a construct without one may not be claimed supported.

Level 3Sixteen constructs, each with a tested meaning — e.g. every accepted period_measure declaration contributes its rows, or validation refuses; never a subset, never silently. It found a seventh instance on its first run: the executor cannot execute a sheetset at all, while the validator validated one including its member-layout check. Level two structurally could not see it — a sheetset is a referent kind, not an enum value.

CaveatParity demonstrates meaning on the cases it exercises. An invariant that holds on a two-row fixture and breaks on a fifty-row one still passes. Property-based generation over the invariants is the obvious next step and is not built.

PRO-3Deterministic

The canary validates the detector, not the domain coverage.

EvidenceThe property suite removes the LIM-4 guard, feeds itself the two-unpivot shape, and requires no_partial_honour to fire. It does. That rules out the embarrassing case — a universal property wired wrong and reporting green regardless of behaviour.

Three claims, kept apart1. The guard prevents the known LIM-4 failure — established. 2. The property catches that failure when the guard is removed — established. 3. Accepted recipes can never be partially honoured — not established. Collapsing 2 into 3 is jumping two floors in one sentence.

CaveatTwo different uncertainties: can the property recognise the defect? (the canary answers this) and can the generator produce every relevant defect shape? (completely open).

PRO-4Deterministic

720 generated cases found no eighth defect — recorded as evidence depth, not discovery.

EvidenceEight properties over four generation buckets, five seeds, plus no_partial_honour on every case. Zero failures. The honest statement is "we pushed variation substantially beyond the hand-authored fixtures and did not find another instance".

FrozenRecorded before grammar-derived generation exists, so that a later eighth instance would be a statement about the testing method — author-written generation → nothing versus grammar-derived → ? — rather than a lucky find.

CaveatMore seeds from the same grammar measures stochastic coverage inside the same imagination. The next qualitatively different evidence is independent generation, not more of this.

PRO-5Deterministic

The defect family has a ladder, and each rung was found by the rung below failing to be enough.

EvidenceEach question was forced by a real defect, not designed in advance: Does it exist? → Does every layer recognise it? (the dispatcher, authorising a recipe its own validator rejected) → Do the layers mean the same thing? (the sheetset, valid and unexecutable) → Does that meaning survive variation? (720 cases) → How much of the domain did we vary over?

CaveatThe last question does not go away unless the input space is finite enough to exhaust. It is not.

What I would defend hardest, and what I would not

Strongest. CON-3 — the structure view cannot carry cell text. It is true by construction and asserted against a live payload, so it does not depend on a model behaving. CON-1 and CON-2 are close behind: the runtime path contains no model, and approval is hash-bound.

Weakest. Every claim about what a model does — USE-5, LIM-5, LIM-6, LIM-7 — is one call, one model, temperature 0. They establish that something can happen. None of them establishes how often, and the steering rate in particular should not be quoted as a probability.

Open, and load-bearing

Named because they are untested, not because they are unlikely. OPEN-2 has since been built and is kept here with its evidence.

OPEN-1Untested

Whether a widened gate is deployable.

Why it mattersEscalating on findings near the answer closes the offset attack. It looks free only because every benign control tested so far is a hidden column, which contributes no finding rows. A benignly hidden row beside a header — a collapsed section separator, entirely ordinary — would false-alarm. That single case decides whether the defence can be left switched on.

OPEN-2DeterministicBuilt

An approval now records what evidence the reviewer actually had.

EvidenceAn approval record binds four hashes — recipe, machine-readable source region, detector findings, and the exact rendered review view — plus the renderer version. Verification fails per relationship, so a broken link says which one. The sharpest case passes: a cell made white-on-white with no value changed leaves the source hash intact and fails on findings, so a document that became less honest cannot verify.

Two verdictshistorically_valid (every link recomputes under the record’s own renderer) is kept separate from meets_current_review_policy (…and that renderer is the current one). An approval made under an older renderer stays valid as history and does not silently acquire the newer renderer’s protections.

CaveatIt records what was shown; it cannot record whether anyone looked. And the source-region hash covers declared sheets’ values — a change in an undeclared corner of the file is outside it.

OPEN-3Untested

How often real provider files actually change.

Why it mattersIt decides COST-1 outright, and it is the one number here that cannot be produced in a lab. Every fixture set in this programme is deliberately loaded with changed files, which makes them good dispatcher tests and useless as prevalence estimates.

Claims drawn from Experiments K, L, M, N, O, P and Q, plus the frozen referent grammar and recipe format. Every number verified against the committed result files at the time of writing; 67 frozen artifacts hash-verified.

Model claims are GLM-5.2 at temperature 0, one call per case. Deterministic claims involve no model at all.
