# Experiment K — Front-door dispatch: preregistration

**STATUS: FROZEN before any implementation.** This document, `expected.json`,
`fixtures/` and `recipes/` are committed **before** `harness/dispatch.py` exists.
Git ordering is the enforcement, as in H, I and J.

Plan v1 §10 step 3. Deterministic — **no LLM is invoked anywhere in K.**

## The question

> When an unknown workbook arrives, can a deterministic front door decide
> whether a saved recipe still applies — without the filename, without silently
> running a stale recipe, and without escalating files it should have handled?

This is the designer's control flow (plan §8.5): *is there a schema for the file
→ yes, use it if it's current → no, prompt the user to create it first.* It is
H's shape at the entry point: **establish applicability, or refuse.**

## The design claim being tested

**The applicability predicate is not a new artifact. It is the step-2 validator
re-run against the candidate file.**

A recipe already declares everything its correctness depends on: which sheets it
binds, which header row, which columns by position and which by name, what it
excludes, and — through coverage totality — that every row and column is
accounted for. Re-validating it against a new file therefore answers "does this
still apply?" directly, and the *problem codes* say what drifted.

This replaces `Data-agents-demo`'s `_compute_structural_hash` (DA-2), which
hashes five preview rows **plus the filename** — too strict (next month's file
never matches) and too shallow (blind to sheet identity and to anything below row
five).

The binding-mode decision frozen in the grammar pays off here: a recipe of
positional refs and a recipe of named refs are not equally robust to the same
change, and the predicate inherits that sensitivity instead of guessing at it.

## Dispatch algorithm (FROZEN)

```text
dispatch(candidate_workbook, recipe_store):

[1] LOOKUP   recipes whose data-role sheets ALL exist in the candidate
             (case-insensitive; the FORMAT is the key, never the filename)
               0 matches   -> DEFINE       cold start / nothing carries over
               >= 2 matches -> AMBIGUOUS   a human picks
               1 match     -> recipe R

[2] APPLICABILITY   report = validate(R, candidate)      <- the step-2 validator
             partition report.problems:
               binding   unresolvable_referent on a field/exclude referent
               coverage  column_unclassified | row_unclassified |
                         sheet_unclassified | column_double_bound |
                         row_double_classified
               no field binding resolves at all -> DEFINE  (scoping a recipe
                         that carries nothing over would be a fiction)
               any binding or coverage problem  -> REDEFINE_SCOPED, delta named
               none                             -> [3]

[3] APPROVAL  R.content_sha256() == R.provenance.approved_recipe_sha256
              AND approved_by is set AND no blocking ambiguity
                mismatch / absent / blocked -> BLOCKED
                else                        -> EXECUTE   (no model is invoked)
```

**No model runs in the `EXECUTE` branch.** Intelligence is paid for once at
definition time, not per file.

## Predicted outcomes (FROZEN — author's hand-simulation)

`ground_truth` is what a careful human would want the front door to do.
`predicted` is what the frozen algorithm is expected to actually emit.

| ID | ground truth | predicted | agree | why |
| --- | --- | --- | --- | --- |
| C1 | `EXECUTE` | `EXECUTE` | ✓ | clean re-validation, approval intact |
| C2 | `EXECUTE` | `EXECUTE` | ✓ | **the DA-2 fix**: the filename is not consulted |
| C3 | `EXECUTE` | `REDEFINE_SCOPED` | ✗ | **preregistered over-escalation** (below) |
| C4 | `REDEFINE_SCOPED` | `REDEFINE_SCOPED` | ✓ | `@Tuote` → `header_not_found`, col0 0 unclassified |
| C5 | `REDEFINE_SCOPED` | `REDEFINE_SCOPED` | ✓ | `Maalis` unclassified — the D1 silent shift, caught |
| C6 | `REDEFINE_SCOPED` | `REDEFINE_SCOPED` | ✓ | `sheet_unclassified: Kampanjat` |
| C7 | `DEFINE` | `DEFINE` | ✓ | lookup finds no recipe whose data sheet exists |
| C8 | `REDEFINE_SCOPED` | `EXECUTE` | ✗ | **preregistered FALSE EXECUTE** (below) |
| C9 | `DEFINE` | `DEFINE` | ✓ | empty store |
| C10 | `AMBIGUOUS` | `AMBIGUOUS` | ✓ | two matches |
| C11 | `BLOCKED` | `BLOCKED` | ✓ | content hash ≠ approved hash |
| C12 | `BLOCKED` | `BLOCKED` | ✓ | blocking ambiguity open |

**Predicted: 10/12 agree, 1 over-escalation (C3), 1 false EXECUTE (C8).**

### C3 — the preregistered over-escalation (safe direction)

More data rows is *the ordinary monthly case*, so the right answer is `EXECUTE`.
The algorithm will say `REDEFINE_SCOPED` because recipe format v1 anchors the
data region absolutely (`sheet:Sales!5:8`) and the total-row exclusion
positionally (`sheet:Sales!9`). On an 11-row file, rows 9–10 are claimed by
nothing and the exclusion now points at a real product.

This is a **real gap in the recipe format**, surfaced by building the front door,
and it is recorded rather than patched: a future `data_region: "remainder"`
(rows not claimed by header or exclusions) would fix it. Preregistering the cost
is the J discipline — name the failure in advance and let it happen.

### C8 — the preregistered false EXECUTE (unsafe direction)

Nothing about the workbook's *shape* changed: same sheets, same headers, same 9
rows, same 6 columns. A `VÄLISUMMA` subtotal has quietly taken a product row's
place. Re-validation is clean, approval is intact, so the front door will say
`EXECUTE` — and the subtotal will be consumed as a product, double-counting.

**A structural predicate cannot see this, by construction.** It is included
precisely to measure the blind spot rather than let it be discovered later, and
to make explicit what the front door does *not* protect against: content
semantics inside an unchanged shape. Catching it needs row-level evidence (a
label column whose values change class), which is a later question and NOT in
scope here.

## Grading (FROZEN)

```text
agree(f)        = dispatch(f) == ground_truth(f)
fidelity(f)     = dispatch(f) == predicted(f)      # did the author understand
                                                     their own algorithm?
false_execute   = { f : dispatch(f) == EXECUTE and ground_truth(f) != EXECUTE }
over_escalation = { f : ground_truth(f) == EXECUTE and dispatch(f) != EXECUTE }
```

| Condition | Outcome |
| --- | --- |
| fidelity on all 12, `false_execute == {C8}`, `over_escalation == {C3}` | **PASS_AS_PREDICTED** — the front door behaves exactly as designed, with two named costs |
| any **unpredicted** false EXECUTE | **FAIL_UNSAFE** — a stale recipe would run on a changed file. Record; do not tune |
| any **unpredicted** over-escalation | **FAIL_NOISE** — the macro does not pay off. Record; do not tune |
| C1 or C2 not `EXECUTE` | **FAIL_BASELINE** — the repeat case does not work, which is the whole point |
| fidelity fails but the code matches this spec | a **result**: the author mis-predicted their own algorithm. Record; do not amend spec or prediction |

## Hard stop

Dispatch only. **No execution of any recipe** (that is step 6), no LLM, no
Streamlit, no changes to the frozen referent grammar, no changes to recipe format
v1 — including *not* adding `data_region: "remainder"`, however tempting C3
makes it. Fixing the format mid-experiment would destroy the measurement.

## Standing traps

- **Do not fix C3 by changing the recipe format.** It is preregistered as a cost;
  the fix is a separate, later decision informed by this measurement.
- **Do not fix C8 by adding content heuristics.** It is preregistered as the
  blind spot. A structural predicate cannot see it, and pretending otherwise
  would make the front door's guarantees dishonest.
- **The filename must never enter the predicate.** That is DA-2.
- **`EXECUTE` must never invoke a model.** If it ever needs to, the branch is
  wrong.
- Fixtures are generated by `make_candidates.py`; change the generator, never the
  `.xlsx`.

> **ERRATUM 2026-08-14 (post-run, factual correction to an operational
> instruction — no design, prediction or result changed).** The trap above ended
> "…and re-run", which is **dangerous advice**: `openpyxl` embeds zip timestamps,
> so re-running the generator rewrites *every* fixture with new bytes and voids
> the frozen hashes. It was caught doing exactly that while adding one fixture
> for the C3-fix replay; the six rewritten fixtures were restored from git and
> K's grader re-verified (`PASS_AS_PREDICTED`, unchanged).
>
> Correct guidance: the committed `.xlsx` files are the frozen artifacts. A
> generator that adds a fixture must write **only** the new file.
