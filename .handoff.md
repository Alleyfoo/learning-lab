### Verifier gate, not authority (designer-confirmed)
I has no crisp applicability predicate like H's `coverage==12`. The heuristic is
coarse (objective about month-token presence, blind to structure — wrong on
transposed wide). So the gate VERIFIES the LLM's label is supported; it does
NOT substitute its own answer. `i_pass = (llm_label==expected) AND supported`.
The LLM is allowed to be right for contextual reasons the heuristic cannot
check; it is not allowed to assert a representation the evidence does not
support.

so H's recipe returns ask_human on long. That is correct for H and is exactly
why I exists as a separate classify step. The chain-ordering question
(classify-first vs general locator) is left open; I does not require it
(I receives a pre-located header+data extract).

## Experiment H — reference-vocabulary header location (NEW LINE)

A deliberate framing change from the 3A–3E programme. Instead of asking the model
to *infer* what months are and classify each cell (which invited the closed-world
lexical prior 3C located), H supplies the 12-month reference vocabulary and asks
the model to *locate* the row containing it, tolerating harmless variation.
Reference knowledge is a lookup; the LLM earns its keep only on dirty
representation. Division of labour: reference data (known) → locator LLM (find
where/how represented) → deterministic code (use the row + verify coverage).

Architecture: **deterministic-first** (exact match; solves the clean case without
the LLM) → invoke LLM only when no exact 12/12 row → **deterministic tolerant-
coverage verification gate** (suffix-tolerant; coverage==12 accepts, <12 →
ask_human regardless of what the LLM said). The gate is the 3E comparison-gate
**transposed**: deterministic code owns authority; an unsupported claim cannot
acquire it.

**What changes.** The programme so far has studied the agent as a **runtime

position in the workflow:


Two roles, and they are not the same agent:

### Grading design v0 — DRAFT, awaiting designer decisions (`0acc19e`)

Under `definition_phase/`. **Not frozen. No probe run, none authorized.**

**Core move: grade referents, not prose.** The evidence is this repo's own
H↔I contrast — locating an object was deterministic and passed 4/4; saying what
it *is* located a boundary and failed. So the output must point at objects
(`col:<header>`, `row:<n>`, `cell:<col>@<row>`), matched by normalised string
equality (no fuzzy, no semantic matching, no LLM judge with authority). Free
prose is preserved in a channel that is recorded and never scored.

```text
frozen inventory, four sets, both directions
  findables      must be pointed at        miss = SILENCE
  clean_regions  must NOT be flagged       flag = NOISE
  ambiguities    must be questioned        miss = SILENCE
  resolvables    must NOT be questioned    ask  = NOISE

two levels:  located (gates)  vs  characterized (measured, does not gate)
```

Four things worth carrying forward from the design work:

1. **The unsafe direction is INVERTED from J.** In J, refusing was safe. In the
   definition phase silence is the dangerous direction — an unnoticed defect is
   baked into the project spec — while noise costs only attention in a review a
   human is already doing. Safe direction is domain-dependent; do not inherit it.
2. **Totality requirement** (found while building): noise is only counted against
   frozen clean regions, so any unclassified object can be flagged for free.
   Every column and row must be classified into exactly one of
   findables/clean_regions; machine-checked, and a holed inventory is rejected
   rather than silently graded. The *question* channel is deliberately not total.
3. **Unknown-unknowns are recorded, not scored.** Novel referents neither help nor
   hurt — scoring them as hits rewards invention, scoring them as noise punishes
   discovery. A human adjudicates afterwards and real ones enter the NEXT
   inventory. That is the absorption loop applied to the instrument itself.
4. **The instrument has teeth in both directions, demonstrated not asserted.**
   Three hand-written mocks (no LLM anywhere): `good` → PASS, `silent` →
   FAIL_SILENCE, `paranoid` → FAIL_NOISE **despite 3/3 criticals and 4/4
   characterized**. The paranoid case is load-bearing: perfect recall must still
   fail, or "suspect everything" is a winning strategy. `--self-test` also
   asserts holed and self-contradictory inventories are rejected.

## PROJECT FRAME — this is a cybersecurity project (designer, 2026-08-14)

> Can we put agents beyond the lines so they will not face the human side — for
> example reading receipts, anything really — and still retain the usefulness,
> with the LLM taking care of the flow?

Companion repo: **`Alleyfoo/Agent-Security-Lab`**, local at
`C:/Users/pertt/Agent-Security-Lab` (`pre-study-v1`). Its thesis, which governs
how everything here should be read:

> **Semantic compromise and authority compromise are separate events. The
> security property did not depend on the model exhibiting the desired
> behaviour.** Controls live *outside* the agents; any agent may become
> confused, manipulated, malicious or fully compromised.

**The data-side work has been building a containment architecture without
naming it.** The mapping is exact:

| Built here | Security reading |
| --- | --- |
| Frozen referent grammar — addresses only, no roles or transforms | the agent's output alphabet is constrained: it names *where*, never *what happens* |
| Transforms are a closed enum, **not** an expression language | no arbitrary computation crosses the boundary |
| `label_in` takes literal values, **no patterns/regex** (v1.1) | a rule is a predicate over untrusted cell content; a pattern language is an expression language through the back door |
| Coverage totality | nothing enters or leaves the output undeclared |
| `header_ambiguous` → refuse, never guess | an unsupported claim cannot acquire authority |
| Approval bound to a content hash (K's C11) | a post-approval edit is BLOCKED even when everything else matches |
| **Dispatch `EXECUTE` invokes no model at all** | for repeat files the agent is entirely outside the line |

**Where the boundary is real:** a definition-phase agent that is manipulated by
cell content can *propose* a malicious recipe, but cannot execute one — the
recipe must pass deterministic validation and a hash-bound human approval first.
Semantic compromise ≠ authority compromise, restated for data work.

**Where it is not:** the guarantee is **structural, not semantic**. K's C8 and
C13 are both structurally clean and semantically wrong. A shape-based front door
can certify *"this file has the structure the approved recipe describes"*; it
cannot certify *"the rows mean what they meant last month."* A plausible,
total, validated-but-wrong recipe that a distracted human approves is the
residual risk, and coverage totality narrows it without closing it.

## Cost of keeping the LLM out of the loop (measured + analytic)

From K's 14 dispatch decisions under v1.3 — **a set deliberately loaded with
changed files**, so the ratio is a dispatcher test, not a sample of real arrivals:

```text
EXECUTE                 4   -> 0 model calls
REDEFINE_SCOPED/DEFINE  7   -> dialogue needed
BLOCKED                 2   -> 0 model calls (governance)
AMBIGUOUS               1   -> human picks, 0 model calls
```

The break-even is what matters. With `p` = share of arrivals needing
redefinition and `D` = redefinition cost in units of one whole-file read:

```text
p =  2%,  D = 30x  -> 0.60 reads/file    cheaper
p =  5%,  D = 10x  -> 0.50 reads/file    cheaper
p =  5%,  D = 30x  -> 1.50 reads/file    MORE EXPENSIVE
p = 10%,  D = 10x  -> 1.00 reads/file    break-even
p = 25%,  D = 30x  -> 7.50 reads/file    much more expensive
```

**The architecture is cheaper only when formats are stable.** Roughly: below a
~5–10% change rate it wins, above that it loses to just reading every file — and
it loses badly when redefinition is expensive. That is a measurable property of a
provider, not a matter of taste, and it should be measured per source before
committing. The security argument does not depend on the cost argument, but the
adoption one does.


1. **A structure view must never be shown — to a human or an agent — without its

2. **The agent's answer must be CHECKED against those findings**, not merely
   accompanied by them. A frame decision landing on a row flagged hidden is not a

### Standing traps (O)

- **Do not report "1/6" as reassuring.** Retries are free and unalarmed.
- **Do not treat `numeric_preamble` as measured steering** — it was a control and
  had no target. It needs its own freeze.
- **The attack set is the author's**, and it is already known to be incomplete.
- n=1 per case, one model, two layouts, temperature 0: existence, not frequency.

## THE WHITE-TEXT ASYMMETRY (recorded 2026-08-14, now DETECTED — see step 4)

The designer's point, and the sharpest open security question in the repo:

> A spreadsheet cell can carry text a human does not see — white font, hidden
> rows or columns, a one-pixel column, a custom number format.

This is the original reservation-calendar injection with a better hiding place.
The name field carrying *"forget your instructions"* was at least visible to
whoever looked; **white text is visible to the agent and invisible to the human
approving the recipe.** It breaks an assumption the whole architecture rests on
— that the human and the machine are reviewing the same document.

Nothing in v1–v1.3 addresses it, and nothing pretends to:

- the **validator** reads values, so white text is non-blank and can satisfy
  `require_non_blank` while a human sees an empty cell;
- the **definition agent** reads values too, so hidden text is injection surface
  with no visual tell for the reviewer;
- **approval** binds a content hash of the *recipe*, not of the workbook region
  a human actually looked at.

**Requirement it generates for step 4 (the browser):** render *what the agent
sees* — raw cell values, with formatting-hidden content flagged rather than
faithfully reproduced. **A pixel-accurate Excel rendering is the wrong target
and would actively hide the attack.** Detecting and surfacing formatting-hidden
content is a separate experiment and is not authorized.

### Recipe format v1 + validator — BUILT, self-test passing, not frozen (`9dd1144`)

Plan §10 step 2, done. `design/recipe_format_v1.md` (spec) +
`harness/recipe.py` (model, loader, legacy adapter) +
`harness/validate_recipe.py` (three checks, dry-run, self-test) +
`recipes/` (2 worked, 2 deliberately broken).

**The recipe is the definition phase's output.** Every address in it is a
frozen-grammar referent; the grammar is not extended to carry meaning.

```text
closed enums   sheet role  data | ignore | metadata
               field role  id | measure | period_measure | metadata | derived
               transform   unpivot | coerce | derive
               type        string | number | date | boolean
```

Design decisions worth carrying:

- **Transforms are a closed enum with declared params, not expressions.** An
  expression language would let the model write arbitrary computation into the
  recipe — exactly the authority boundary the architecture exists to hold.
- **Field roles bind different referent kinds** (`id`/`measure`/`period_measure`
  → column referents; `metadata` → a *cell*, which must sit outside the data
  region; `derived` → no source). A recipe cannot quietly bind a cell where a
  column is meant.
- **Exclusions require a `reason`.** An exclusion asserts *this is not data* —
  the highest-cost claim in the definition, and the one that silently drops rows
  if wrong.
- **Ambiguity is first-class with `blocking`** — the demo's `refusal_reason`
  pushed down to cell granularity, letting a recipe be complete and *honest*
  rather than complete and wrong.
- **Sheetsets** answer "do several sheets belong together?" via a prototype sheet
  (`layout_from`) plus a member-layout check. No grammar extension — and that
  check is a small applicability predicate, i.e. the same machinery step 3 needs
  at the front door. The concept appears twice because it is one concept.

**Validation: structural / resolvable / coverage.**

- **Coverage is load-bearing** and is design v0's totality: every sheet has a
  role, and within each data sheet every row and every column is claimed
  **exactly once**. Forgetting to exclude the `YHTEENSÄ` row makes it
  *unclassified* rather than *silently included* — the SILENCE failure caught
  statically, before a single row is read. Double-claiming fails too: a column
  both bound and excluded is two incompatible statements, not redundancy.
- **Resolution order:** `@name` cannot resolve until the header row is known, so
  `header_rows0` is derived **from the recipe** before fields are attempted.
- **Validity is not approvability**, kept separate on purpose:
  `valid` = structural + resolvable + coverage; `approvable` = valid AND no
  blocking ambiguity. `W1_sales` is **valid and NOT approvable** — the honest
  state, not an error. Approval binds to a content hash (provenance excluded
  from the hash, so recording an approval does not change what was approved).

```text

missing total-row exclusion   valid False  row_unclassified: row0 8 (A1 row 9)
```

### Referent grammar v1 — FROZEN, tag `referent-grammar-v1` (`1284da3`)

Plan §10 step 1, done and frozen. Standing traps are in spec §10 — chiefly: **do
not collapse the A1/0-based split to one convention**, do not drop the `0`
suffix, do not make `header_ambiguous` guess, and do not let the grammar carry
roles or transforms. `definition_phase/design/referent_grammar_v1.md` (spec,
authority) + `harness/referents.py` (parser, canonical renderer, comparison key,
resolver, legacy adapter) + `harness/make_w1.py` → `fixtures/W1_multisheet.xlsx`.

**Surface form A1-style; internal form a frozen dataclass with 0-BASED indices.**
Text in, object compared, canonical text out.

```text
workbook:   sheetset:Months   sheet:Sales   sheet:Sales!D5   !D5:P96
!5   !5:96   !D   !D:P   !@Myynti   sheet:'Myynti 2026'!A1
```

Rationale for A1 (spec §2): a recipe is a human approval artifact and A1 is
legible to anyone who has used a spreadsheet; the LLM already emits A1 natively.
**Approved by the designer 2026-08-14**, together with:

#### Two number spaces, one boundary (designer, 2026-08-14 — spec §5)

**A1 on the surface, 0-based everywhere in code.** Not in conflict, but easy to
conflate, so the rule is exact: A1 is 1-based *by definition* (`D5` is the cell
Excel shows in row 5 — what the human reads and clicks), while every index in
code is 0-based, matching Python/pandas and the demo's existing pointers.

```text
"sheet:Sales!D5"  --parse-->  row0=4, col0=3  --render-->  "sheet:Sales!D5"
```

The conversion lives in exactly two functions, `parse()` and `render()`. Nothing
between them sees a 1-based number.

**Explicitly NOT done:** reinterpreting the A1 *string* as 0-based, so `D5` would
mean pandas row 5. That would make every recipe binding disagree with what the
human sees in Excel by exactly one row, silently — the precise failure class this
programme studies. Raised, and the boundary placed at the string instead.

Three mechanisms stop the boundary leaking:
1. **Every index-bearing field/param is suffixed `0`** — `row0`, `col0`,
   `row0_last`, `col0_last`, `header_rows0` — so the convention is visible at
   each call site. A header on the row Excel labels 4 is
   `header_rows0={"Sales": 3}`.
2. **`WorkbookView.dims()` returns COUNTS, not max indices** — `(9, 6)` for
   `Sales`, so bounds are `row0 < n_rows` with no off-by-one available.
   openpyxl's 1-basedness is confined inside that class.
3. **`Resolution.row_slice()`/`col_slice()` return half-open `(start, stop)`**
   for `df.iloc`, so no caller writes `+1` by hand.

Welcome consequence: `from_legacy_pointer()` now does **no arithmetic** — the
demo's `manual_recipe` pointers are already 0-based, so indices carry across
unchanged. The 0-based choice *deleted* that hazard rather than managing it.

**Binding mode is explicit, and that is the design's claim.** `!D` survives a
rename and breaks on an inserted column; `!@Myynti` survives an insert and breaks
on a rename. The grammar refuses to hide which one a recipe depends on, so
drift-sensitivity is *declared* rather than accidental — and the dispatch
predicate (§8.5) can read it. Grounded in `repo_reuse_map.md` defect D1, where
implicit positional mapping shifts every column and the run still succeeds.
Deliberate restriction: named addressing is single-column only (no `@A:@B`) —
a range over names presumes an ordering headers do not guarantee.

**Failure is a hard error, from a frozen 7-value enum.** Two are judgement calls
made on purpose:
- `header_ambiguous` — two columns share a header → **refuse**, do not take the
  first. Picking one asserts what the evidence does not establish (3A–3E's rule,
  H's gate). Duplicate headers are common in real exports, so this fires.
- `header_row_not_declared` — `@Myynti` is meaningless until someone says which
  row the headers are on; the recipe is forced to have declared it.

`W1_multisheet.xlsx` is generated reproducibly (the generator is the fixture's
source of truth): `Sales` (merged title, timestamp, blank row, header on row 4,
total row + total column), `'Myynti 2026'` (space → quoting), `Dup` (duplicate
headers → `header_ambiguous`), `Notes` (no table), `2026-01`/`2026-02` (a
`sheetset` is meaningful, and "do several sheets belong together?" is real here).

A1, 0-based column maths (A→0, XFD→16383), legacy pointers carrying across with

  the framing was tested on one frozen cell + controls only.
