### New / changed files

- `supervisor/incoming.py` (NEW) -- read-only incoming-data scanner. `scan(workers,
  data_root) -> {data_library, inboxes}`. Does **not** import `fleet` (duck-types
  worker objects: `.directory`, `.identity`, `.name`). Uses openpyxl read-only to
  enumerate xlsx sheet names.
  - `data_library`: one entry per top-level `data/` subdir -> `{dir, files:[{name,
    kind, sheets}], has_adapter, has_model, worker}`. Worker link = trigger-path
    containment OR filename cross-ref (worker with the most matching file names;
    name-token tiebreak on a tie; `None` when genuinely ambiguous). `has_model`
    surfaces the genuine "model exists but not deployed as a worker" gap
    (`data/xlsx-purchases/`, `data/xlsx-statement/`). `worker=None` is rendered as a
    neutral "no worker link", NOT a confident "not yet modelled" -- some unlinked
    dirs (e.g. `data/april-invoicing/`, `data/timesheets/`) are seed/reference JSON
    for modelled workers whose structural link is not machine-findable.
  - `inboxes`: one entry per worker with files -> `{worker, customer, files:[{name,
    kind, stage, sheets}]}`. Modelled by construction (each inbox belongs to a worker).
  - Deterministic `--self-test` (temp data tree + fake worker dirs; covers trigger
    link, filename cross-ref, token tiebreak, ambiguous->None, badges, inboxes,
    missing data_root).

## Known issues / nuances

- **The incoming browser is a companion panel, not part of the map graph.** PRODUCT.md
  asks to "extend the visual mental model leftward so the operator can also see incoming
  files that have not yet been modelled." v0.2 surfaces that data beside the map; it does
  not yet draw unmodelled data as map nodes connected to modelled work. That graphical
  integration is a future step.
- **Assessment placement is "on top", not "beside" (right column).** PRODUCT.md's target
  workspace draws SUPERVISOR as a right column beside the map. The approved v0.2 plan
  placed it on top (per the user's "beside/on top") to give the vis-network map maximum
  width (its fixed columns span ~1400px and cramped badly in a 3-column layout). A future
  iteration could move it beside once the map is company-scoped/filtered to a narrower
  view.
- **The worker link is a heuristic.** `data/xlsx-fazerish/` links to `fazerish-invoicing`
  via a name-token tiebreak (both april and fazerish workers share `may-order-lines.xlsx`
  in `processed/`). `data/april-invoicing/`, `data/timesheets/`, `data/training-room/`,
  `data/kesko-reconciliation/`, `data/training-rooms-multi/` show "no worker link"
  honestly, even though some are seed/reference data for modelled workers -- there is no
  machine-findable structural link in the current on-disk layout. If you want a real
  data-dir -> worker link, the worker identity would need an explicit source-path field.
- **`use_container_width=True` deprecation** warning on the Rules tab dataframe is
  inherited from v0.1 (harmless; still renders). Not in v0.2 scope.
- **glm-5.2:cloud calling `file_assessment`** is still only self-test-verified (stub
  model); the real-model check remains the open v0.1 item (per [[v0-operating-posture]]).
