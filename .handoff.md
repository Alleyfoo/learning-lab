## The v0.6 shape that landed

- **Source definition (contract)** lives in `input_contracts/v<N>.json` per
  worker version, separate from `versions/v<N>.json` (taskmodel.parse would
  contaminate the task body otherwise). `xlsx.specs_from_contract` reads it.
- **Source instance** = one open input set per worker (`fleet/input_set.py`):
  `input_set.json` holds role→{document,digest,sheet,header_row,materialized_as}.
  Sole slots need an explicit `.role` sidecar (filename is not authority);
  shared slots bind all roles on one upload.
- **Materialization** is deterministic JSON to `w.base / sources[role].path`,
  overwritten per run (no archive). Raw arrivals are retained by digest:
  `processed/<digest>.<ext>` via `inbox.retained_name` (Phase 6).
- **Run** carries `run_input` atomically on the one `runs.jsonl` line
  (Phase 5): `{input_set, input_contract, model, fingerprint, slots}`. The
  fingerprint (sha256 over {model version, input-contract version, sorted
  role→source-digest bindings}) is what recovery matches on.
- **Recovery** (Phase 4.5, `inbox._recover_contract`) is set-wise: complete+no
  match→run once; complete+match→terminalize no run; partial→preserve;
  corrupt→exception. The fingerprint guard overrides the noncommitting
  safe_to_retry re-run, so a complete set runs EXACTLY ONCE across crash +
  recovery.
- **Operator surface** (Phase 7): `operate.save_to_inbox(role=...)` writes the
  sidecar; `operate.slot_choice(w)` reports sole/shared/mixed; the v0.5 inbox
  panel renders a slot picker for sole slots and a shared caption for shared.
