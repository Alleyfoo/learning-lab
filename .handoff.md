## Known issues / caveats

- **No-interpretation canary false positives on the model's freeform `metric`
  arg** (same class as S15 FINDINGS §7): a measurement's `metric` string may
  contain an interpretation word (e.g. a measurement-feature description), which
  `file_measurement` echoes into its return string, tripping the blunt substring
  canary. It is a RECORDED FLAG (`canary_no_interpretation` on the route result),
  not a gate -- routing is not blocked -- and the UI does not surface it. The
  real-model e2e tripped it once on IMP-005 (a measurement). Not a bug; matches
  the documented S15 class.
- **Activation against the real rulebook is left to the human** (genuinely
  human-gated by design). The deterministic `routing.py --self-test` verifies
  activation grows the rulebook 5->6 with the proven rules intact; a real
  activation is the user's to trigger via the UI Activate button.
- `supervisor/runs/` is created on demand by `supervision.review` (real runs
  saved there). It did not exist before this session; it is untracked.
