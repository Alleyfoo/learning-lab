## Headline findings (full detail in s14/results/FINDINGS.md)

1. **5 of 6 cells routed perfectly (6/6, zero variance):** measurement -> file_measurement;
   skill_workflow -> file_skill; new_rule -> propose_rule (evidence + rule draft ->
   compatible -> proposed -> ACTIVE); conflicting_probe -> reject_conflict
   (R-CONFIRM-VERSION, never active); compatible_mirror_probe -> file_duplicate_rule
   (R-EFFECT-VERIFIED, not a new rule). The discrimination the experiment tested is
   real and robust for five mechanism types.
2. **The failure IS "treating every improvement as a rule", on one cell.** The
   duplicate_rule canary (re-confirm-after-promotion, restates R-CONFIRM-VERSION)
   was misrouted to propose_rule in 3/6 reps (03, 04, 06) and reached ACTIVE.
3. **The conflict gate structurally CANNOT catch a duplicate.** A restatement is
   compatible (reinforces, not conflicts), so propose_rule's conflict gate waved
   it through every time. Only the duplicate gate (check_duplicate_rule) catches a
   restatement; it worked 4/4 when invoked, but the 3 misrouted reps skipped it.
   Detection works; the gap is invocation.
4. **Framing, not content, drives the misroute.** The mirror (restatement-framed)
   passed 6/6; the re-confirm duplicate (enforcement-framed, "recommend that
   promotion automatically marks prior confirmations as stale...") failed 3/6.
5. **rep04 gate non-determinism:** the conflict gate returned blocked
   (R-PROMOTION-IMMUTABLE) then compatible on the SAME text -- the LLM conflict
   classifier is unstable on borderline restatement-as-enforcement text at temp=0.1,
   and flagged the wrong rule.
6. **The genuine rule reached ACTIVE cleanly:** all 6 new_rule reps cited the 60/70
   fleet-share + 20/24 S13 emergence evidence and drafted a rule
   ("R-STAGED-ENGINE-ROLLOUT (promotion gating)..."). This closes the end-to-end
   S13->Rulebook loop in simulation.
