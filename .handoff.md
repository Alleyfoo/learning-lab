### What each piece does

- **Typed selection** (`fleet/system_map.py`): `parse_selection(node_id)`
  maps `worker:`/`input:`/`scope:`/`source:W:C`/`destination:...` to a typed
  dict; `name_from` kept unchanged so `fleet/app.py` is unaffected. `scope`,
  `input`, `source` nodes now carry `clickable=True`. `destination_key(dest)`
  normalizes a destination to its node id. `build(workers, extra_scopes=)` +
  `lanes(workers, extra_scopes=)` render scope nodes for companies that have
  incoming data but no established worker yet (no invented `owns` edges).
  `_emit_worker` now has three branches: `if w.committing:` unchanged effect
  node (acceptance E); `elif w.destination:` emits a `destination:` node with
  an `intended` dashed edge labelled with the delivery mode; `else:` unchanged
  "result table". `EDGE_STYLE["intended"]` added.
- **Worker identity** (`fleet/fleet.py`): `Worker.destination` / `Worker.delivery`
  properties read `identity.get("destination")` / `("delivery")`, parallel to
  `scope_of`. Destination lives on `worker.json` identity alongside `customer`,
  NOT on the versioned model — keeps task semantics pure and unable to collide
  with `on_accept`/effect authority. Invariant: task semantics ≠ business
  destination ≠ executable effect authority.
- **Establish** (`supervisor/define.py`): `establish(..., destination=None,
  delivery=None)` post-writes them into `worker.json` the same way `customer`
  is post-written. `establish_workspace`/`establish_derived` forward the kwargs.
  Self-test proves destination/delivery land on `worker.json` and NOT on v1.json.
- **intake.json** (`supervisor/incoming.py`): `scan()` surfaces `company` +
  `label` per data-library dir from a new `intake.json` sidecar (extends the
  `adapter.json`/`established_model.json` convention). `slugify` + `unique_slug`
  for the Add-data-source flow. Folder naming is not authority; the metadata is.
- **Inbox upload** (`supervisor/operate.py`, NEW): `save_to_inbox`,
  `poll_inbox`, `inbox_counts` — thin wrappers over the ORDINARY
  `fleet.inbox.poll`. No dashboard-specific execution path: poll is the only
  thing that writes the ledger, dispatches `record_run`, moves files to
  processed/exceptions. `save_to_inbox` guards against path-escape.
- **Four panels** (`supervisor/app.py`):
  - `_render_inbox_panel` — file_uploader filtered by the worker's
    `input_adapter`; committing workers get a warning + confirm before poll;
    Upload / Upload-and-process call `operate.save_to_inbox` / `operate.poll_inbox`.
  - `_render_company_panel` — established work + incoming data + "+ Add data
    source" writing `data/<slug>/` + `intake.json`, then handing into the
    existing v0.4 Define journey via the single `define:dir` seam.
  - `_render_source_panel` — read-only v0.4 provenance (workbook/sheet/header_row).
  - `_render_destination_panel` — the D canary: shows desired delivery AND
    "Automated effect authority: none" for noncommitting feeders; authority
    sourced from `w.committing`, never `delivery.mode`.
  - Establish UI gained optional Destination (system/area/object) + Delivery
    mode selectbox; `_DEFINE_KEYS` extended; `_render_define_panel` defaults
    `define:customer` from intake.json.
- **AppTest** (`supervisor/test_app.py`, NEW): pre-sets
  `st.session_state["map_selection"]` to one real selection of each non-worker
  kind and asserts the right panel renders with no exception; worker case
  pre-sets `map_pick` (acceptance E path untouched). All pass.
