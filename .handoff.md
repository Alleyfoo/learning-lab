`^-?\d+\.\d+$`) and **not** `quantity` (`"3"`, `"7"`, `"2"`). The program
described one operand of the declared multiplication and not the other. All three
probes blocked on `quantity` as a result — correct behaviour on an observer gap,
which X-4 had preregistered as over-blocking.

Fixing the observer to characterise integer strings and re-running is a **new
experiment, not a retry**. The interesting version pairs it with the untested
question X raised: does the inspector over-block when overlap is 3/3 on one
candidate key and 2/3 on another — i.e. when the join IS decidable? X only tested
a perfectly balanced ambiguity.
